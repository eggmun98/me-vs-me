## 확정된 규칙 (v0.3)

### A. 달성률

| 항목 | 결정 |
| --- | --- |
| 계산식 | `완료한 미션 수 ÷ 그날 확정된 전체 미션 수` |
| 분모 | **진행 전 미션 포함** (하루가 진행되며 0%부터 차오름) |
| 부분 달성 | **없음.** 완료 / 미완료 이분법 |
| 난이도 | 달성률에 **반영 안 함** (랭킹 활동 점수에만 사용) |

### B. 승패 판정

| 달성률 | 결과 |
| --- | --- |
| 50% 초과 | 승 |
| 정확히 50% | 무 |
| 50% 미만 | 패 |

- **기준은 운영자가 고정한다. 사용자가 바꿀 수 없다.**
- 무승부는 **미션 개수가 짝수인 날에만** 발생한다 (홀수는 정확히 50%가 나오지 않음)

### C. 하루의 경계

| 항목 | 결정 |
| --- | --- |
| 하루 끝 | **사용자 타임존 기준 자정** |
| 그날 미션 확정 | 하루 시작 시 `DailyMission`으로 스냅샷. **삭제·비활성화는 다음 날부터 반영** |
| 당일 미션 추가 | **허용** (분모가 늘어 불리하므로 악용 불가) |
| 미션 0개 | **쉬는 날** — 전적 제외 / 연승 유지 / 잔디 무색 |
| 지난 기록 수정 | **7일 이내 가능, 이후 불가** |

### D. 전적 · 연승

| 항목 | 결정 |
| --- | --- |
| 일일 승률 | `승 ÷ 전체` (무는 분모에 포함, 쉬는 날은 제외) |
| 연승 — 승 | +1 |
| 연승 — 무 | **끊김** |
| 연승 — 패 | **끊김** |
| 연승 — 쉬는 날 | 유지 (증가 없음) |

### E. 잔디

승리만 농도 3단계, 패·무는 각 1단계, 쉬는 날은 무색.
색 제약은 `01-service-plan.md` 8.1 참고 — 명도 위계 / 승·무는 색상 분리 / **패배에 빨강 금지** / 색 토큰화.

## 남은 항목

### R-1. 랭킹 최소 조건 — **Phase 2**

미션 1개만 만들고 매일 완료하면 승률 100%가 된다.
랭킹에 최소 표본 조건이 필요하다 (활성 미션 수 / 활동일 수 / 일일 승부 참여 횟수).

18장의 활동 점수가 이를 일부 흡수하지만, 조건 자체는 별도로 정해야 한다.
**MVP에는 랭킹이 없으므로 지금 정하지 않아도 된다.**

### R-2. 업적 목록 확정 — **Phase 2**

19장의 7개는 예시다. 실제 목록과 판정 시점(실시간 / 일일 정산 배치)을 정해야 한다.

### R-3. 활동 점수 공식 — **Phase 2**

원문 18장에서 **"실제 사용자 데이터를 확보한 후 조정"**으로 명시적 보류.

### R-4. 온보딩 — 화면설계 단계

- 최초 사용자에게 기본 루틴 템플릿을 제공할 것인가
  (20장 루틴 공유는 Phase 3라 MVP에는 공유된 루틴이 없다)
- 첫 미션 개수 가이드 — 37장 원칙(과욕 방지)과 직결

### R-5. 화면별 Phase 분리 — 화면설계 단계

문서 안에 Phase가 섞여 있는 곳이 있다.

- 27장 MY 메뉴의 `장기 목표` → 22장 기준 Phase 3
- 25장 기록 화면의 `시즌 기록` → 10장 기준 Phase 2

화면설계서에서 **MVP판 / Phase 2판 / Phase 3판을 분리해서** 그린다.

### R-6. 잔디 실제 색상값 — 화면설계 단계

8.1의 제약 조건을 만족하는 구체적 색을 정한다.

### R-7. 시즌 확정 시점 — DB 설계 단계

기록을 7일까지 수정할 수 있으므로 **시즌 결과는 월말 + 7일이 지나야 확정**된다.
"확정 전까지 잠정 표시"로 갈지, "항상 실시간 계산"으로 갈지 정한다.

> 데이터 규모가 작아(사용자당 연 365행) 실시간 계산으로도 충분할 가능성이 높다.
